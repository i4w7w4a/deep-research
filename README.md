# Deep Research

Личная память исследований и находок. Полный материал можно прочитать в контексте, а к отдельной мысли — вернуться по карточке со ссылкой и своим комментарием. Корень репозитория открывается в Obsidian как хранилище. GitHub хранит историю тех же Markdown-файлов.

| Куда положить | Что здесь хранится |
| --- | --- |
| `research/` | Полные отчёты Deep Research. Если у отчёта есть иллюстрации, положи их рядом с ним в одну папку. |
| `sources/` | Другие источники — статья, запись разговора, файл, ссылка на видео или собственное наблюдение. Для внешнего материала достаточно заметки со ссылкой. |
| `chunks/` | Выбранные фрагменты из любого источника. У одного отчёта может быть несколько карточек, а у короткой находки — одна. |
| `templates/` | Пустые шаблоны источника и фрагмента для копирования в Obsidian или GitHub. |

## Как сохранить находку

1. Если нужен весь материал, положи его в `research/` или `sources/`. Готовый отчёт можно сохранить в исходном виде. Для собственной записи или ссылки скопируй [шаблон источника](templates/source.md).
2. Если хочется вернуться к конкретному месту, скопируй [шаблон фрагмента](templates/chunk.md) в `chunks/` и дай файлу понятное имя. Укажи источник и место — заголовок раздела, страницу или таймкод. Для внешней ссылки карточку можно создать сразу.
3. Вставь столько текста, сколько нужно для понимания мысли вместе с её условиями. Для изображения или записи опиши увиденное своими словами и пометь это как описание. Рядом запиши, чем фрагмент тебя заинтересовал. Если остался вопрос, укажи, при каком событии к нему вернуться.

Для локальных файлов используй относительные Markdown-ссылки. В поле `id` новой карточки один раз вставь UUID (в Linux его выдаёт `uuidgen`). При переименовании файла сохрани ID. Для источника, у которого уже есть такой ID, перенеси его также в поле `source_id` фрагмента. По нему можно найти оригинал, даже если ссылка устарела.

## Как здесь применяется 4i7

Полный источник сохраняет контекст. Карточка связывает конкретное место с тем, что заметил наблюдатель. Если позднее появится противоречащее свидетельство, эти две записи позволят вернуться к исходному месту и пересмотреть вывод. Так в проекте связаны Скелет связей, Судья и Хранитель. [Рабочая матрица 4i7](https://github.com/i4w7w4a/4i7_psys/blob/bb9c34dac403a208feb8c51787b69e5386ad58c9/docs/09-matrix.md) · [Порядок работы агента](AGENTS.md)

В Git входят четыре каталога из таблицы, этот README, инструкция агента и правила Git. Другие файлы в корне, в том числе локальные заметки и настройки Obsidian, остаются на этом компьютере. Первый вопрос для проверки на реальном материале — удастся ли из карточки открыть точное место и вспомнить, зачем фрагмент был сохранён.
